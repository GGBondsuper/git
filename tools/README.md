# GitHub 网络工具包

> 给「GitHub 时通时不通」这种情况准备的一组小工具。
> 不需要懂原理，双击对应的 `.bat` 就行。

## 三个入口

| 双击这个 | 干什么 | 需要管理员权限 |
|---|---|---|
| `check-github.bat` | **体检**：看看现在哪条线是通的 | 不需要 |
| `push-github.bat` | **推代码**：自动挑一条能用的线，然后 `git push` | 不需要 |
| `sync-github.bat` | **同步**：先拉后推，一条命令对齐两边 | 不需要 |
| `fix-github.bat` | **全局修复**：改 hosts，让浏览器和 VS Code 也通 | **需要**（右键 → 以管理员身份运行） |
| `restore-github.bat` | 撤销 `fix-github.bat` 的修改 | **需要** |

## 什么时候用哪个

```
git push 卡住 / 报 502 / 超时
        │
        ├─ 只想把代码推上去 ──────────► push-github.bat
        │
        ├─ 想让浏览器、VS Code 也能开 ► fix-github.bat（管理员）
        │
        └─ 想先搞清楚到底怎么了 ──────► check-github.bat
```

## 它到底在解决什么

GitHub 不是一个网站，是一群域名，各自解析到不同的服务器：

| 域名 | 用途 | 常见状况 |
|---|---|---|
| `github.com` | 网页、`git push` / `clone` | **最容易出问题的那一个** |
| `api.github.com` | 接口查询 | 通常正常 |
| `codeload.github.com` | 下载源码压缩包 | 通常正常 |
| `raw.githubusercontent.com` | 下载单个文件 | 时好时坏 |

问题往往不是「上不了 GitHub」，而是 **`github.com` 解析到的那个 IP 的 443 端口连不上**，
而同一网段的其他 IP 反而是通的。

所以本工具做的事很简单：**换一个能连的 IP**。

## 两个容易踩的坑

**① TCP 通 ≠ 真的通**

有些网络设备会回应 TCP 握手（看起来"连上了"），但随后掐断 TLS 加密层。
所以本工具的探测会走**完整 HTTPS 请求**，拿到 HTTP 状态码才算数。

**② IP 会变**

GitHub 的地址不是永久的。今天能用的 IP，过几天可能就不行了。
所以脚本**每次运行都现场重测**，不需要你记住任何地址。

## 原理备忘

`git-remote.ps1` 用的是 git 2.44+ 才支持的配置项：

```
git -c http.curloptResolve="github.com:443:140.82.114.3" push
```

意思是「连接 github.com 时，别去查 DNS，直接连这个 IP」。
它只影响这一次命令，不改系统设置，也不需要管理员权限。

`fix-github-host.ps1` 则是把这个映射写进系统 hosts 文件，
好处是所有程序（浏览器、VS Code、命令行）都生效，代价是需要管理员权限。

## 如果所有线都不通

那就不用折腾这些脚本了，问题在网络出口本身：

1. 换手机热点试一次（30 秒就能判断是不是校园网/宽带的事）
2. 打开 Watt Toolkit（原 Steam++）或 FastGithub 这类加速工具
3. 过一阵再试 —— 这条线路是间歇性的，不是恒定的

**你的提交不会丢。** Git 把历史存在本地，等多久都在。
